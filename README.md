# Yieldia Devnet Data

Public issuer and prospectus documents registered with Yieldia on Solana devnet.

## Layout

Every non-hidden directory at the repository root represents one issuer. The issuer metadata lives directly in that directory; every nested directory represents one prospectus.

```text
<issuer>/
├── issuer.json
└── <prospectus>/
    ├── prospectus.md
    └── proof-pack.json
```

Use lowercase kebab-case directory names. Keep the document filenames shown above so paths stay predictable.

## Add an issuer

Run the `just` commands below from the `mikasa` repository. Replace every value in angle brackets.

### 1. Create the issuer authority

Generate the authority keypair in a directory outside both repositories:

```sh
just solana keygen /absolute/path/to/yieldia-keys/devnet/issuers \
  new --outfile <issuer>-authority.json

just solana keygen /absolute/path/to/yieldia-keys/devnet/issuers \
  pubkey <issuer>-authority.json
```

Keep the generated seed phrase outside this repository as a recovery backup. If you set a BIP39 passphrase, recovery requires both values.

The seed phrase can also help move this devnet authority into a browser wallet for the Realms UI, but verify that the imported account has the exact authority address printed above. Wallets may use a different derivation path and produce another address from the same phrase; if that happens, use the wallet's private-key import instead.

Record the printed authority address and fund it with enough devnet SOL to pay rent and transaction fees. Never commit the keypair or recovery material.

### 2. Derive the Issuer account

```sh
just yieldia issuer address <authority-address>
```

The result is the deterministic Issuer PDA. It is not another keypair.

### 3. Add the metadata

Create the metadata draft with the Yieldia CLI:

```sh
just yieldia issuer create .cache/<issuer>-issuer.json
```

Keep every field generated by the CLI and replace every `REPLACE_ME` value in `.cache/<issuer>-issuer.json`. Set `issuer_account` to the PDA from step 2, not the authority address, and set `metadata_uri` to `https://raw.githubusercontent.com/yieldia-labs/devnet-data/main/<issuer>/issuer.json`.

### 4. Optionally validate the metadata

Before committing, validate the completed document and inspect its exact-byte metadata hash:

```sh
just yieldia issuer validate \
  .cache/<issuer>-issuer.json
```

### 5. Publish the exact bytes

Commit and push the metadata before registration so its raw GitHub URL is publicly available:

```sh
mkdir -p /absolute/path/to/devnet-data/<issuer>
mv .cache/<issuer>-issuer.json \
  /absolute/path/to/devnet-data/<issuer>/issuer.json

git -C /absolute/path/to/devnet-data add <issuer>/issuer.json
git -C /absolute/path/to/devnet-data commit -m "Add <display-name> issuer metadata"
git -C /absolute/path/to/devnet-data push
```

### 6. Simulate registration

```sh
just yieldia issuer register \
  https://raw.githubusercontent.com/yieldia-labs/devnet-data/main/<issuer>/issuer.json \
  --rpc-url https://api.devnet.solana.com \
  --signer <authority-address>
```

Simulation and registration are now the same command, told apart by their flags: without `--submit` it builds and simulates, with it signs and submits. `--signer` is the public address recorded in step 1. The CLI uses it to derive and verify the Issuer PDA while building an unsigned transaction; simulation does not read the authority keypair, sign, or submit anything.

Check that the output contains the expected authority, Issuer PDA, metadata URI and hash, devnet genesis hash, and a successful simulation.

### 7. Register the issuer

```sh
just yieldia issuer register \
  https://raw.githubusercontent.com/yieldia-labs/devnet-data/main/<issuer>/issuer.json \
  --rpc-url https://api.devnet.solana.com \
  --keypair /absolute/path/to/yieldia-keys/devnet/issuers/<issuer>-authority.json \
  --submit
```

The same command with `--keypair` and `--submit` signs and submits it. The two flags are required together: a keypair without `--submit` is refused rather than quietly building unsigned. Verify the Issuer PDA on Solana Explorer. If submission succeeds but confirmation is unavailable, check the reported signature and PDA before rebuilding the transaction with a new blockhash.

After registration, keep the published bytes stable. Changing them changes the metadata hash and requires a matching onchain `issuer_update_metadata` transaction.

### 8. Optionally fund the issuer with test YTUSD

If the issuer needs the devnet payment token for prospectus testing, transfer YTUSD from a funded wallet:

```sh
just solana token-transfer \
  /absolute/path/to/<funding-keypair>.json \
  --url https://api.devnet.solana.com \
  --fund-recipient \
  6To6oV5uLtZCTXg7kD6cSnKqsN6UWxjkEAZnDsWF81WM \
  <amount-in-ytusd> \
  <authority-address>
```

The funding keypair owns the source YTUSD and pays the transaction fee and recipient account rent. `--fund-recipient` creates the issuer authority's YTUSD associated token account when needed. Record the printed `Recipient associated token account`; that token-account address, not the authority address, can be used as a prospectus treasury.

## Add a prospectus

Run the commands below from the `mikasa` repository. The Issuer must already be registered and `Active`. The current CLI creates each Issuer with no additional authorized authors, so register its prospectuses with the issuer authority keypair. That authority must have devnet SOL for rent and fees.

### 1. Prepare local drafts

Keep the working copies under the `mikasa` `.cache` directory so the Dockerized CLI can read them:

```sh
mkdir -p .cache/<issuer>-<prospectus>

just yieldia prospectus create \
  .cache/<issuer>-<prospectus>/prospectus.md
just yieldia proof-pack create \
  .cache/<issuer>-<prospectus>/proof-pack.json
```

### 2. Define the prospectus and its terms

In `prospectus.md`, choose a stable `prospectus_id`, complete `title` and `summary`, set the registered Issuer PDA and display name, and use these canonical URLs:

```text
document_uri: https://raw.githubusercontent.com/yieldia-labs/devnet-data/main/<issuer>/<prospectus>/prospectus.md
proof_pack_uri: https://raw.githubusercontent.com/yieldia-labs/devnet-data/main/<issuer>/<prospectus>/proof-pack.json
```

Complete every field under `terms`. Numeric values are quoted decimal strings from `1` through `u64::MAX`. `token_issuance_amount` is expressed in instrument base units, and `token_unit_price` is expressed in payment-token base units per instrument base unit; their product must fit in `u64`. `claim_window`, `sale_window`, and `settle_window` are Solana slot counts. `issuer_treasury` must be an initialized classic SPL token account whose mint equals `token_price_asset`; `yield_asset` must be an initialized classic SPL mint and may be the same mint.

The body is free-form Markdown, but remove the drafting note and every `REPLACE_ME` before publication.

### 3. Derive the shared hashes

After `prospectus_id` and every term are final, derive their canonical hashes:

```sh
just yieldia hash prospectus \
  .cache/<issuer>-<prospectus>/prospectus.md
```

Copy `prospectus_id_hash` and `terms_hash` into both documents.

### 4. Derive the Prospectus account

Derive the deterministic Prospectus PDA from the registered Issuer PDA and the full `prospectus_id_hash`, including its `sha256:` prefix:

```sh
just yieldia prospectus address \
  <issuer-pda> \
  <prospectus-id-hash>
```

Copy the result into `proof-pack.json` as `prospectus_provenance.prospectus_account` and use the same address in any proof-pack evidence entry that names the prospectus. A Prospectus is a PDA; it has no keypair.

### 5. Complete and hash the proof pack

Set `author_pubkey` to the issuer authority address from the issuer workflow. Keep `prospectus_id`, `prospectus_provenance.issuer_account`, `prospectus_provenance.document_uri`, `prospectus_provenance.terms_hash`, and `issuer_context.issuer_name` equal to their `prospectus.md` counterparts. Complete every remaining proof-pack field, then validate it against the issuer metadata snapshot:

```sh
cp /absolute/path/to/devnet-data/<issuer>/issuer.json \
  .cache/<issuer>-<prospectus>/issuer.json

just yieldia proof-pack validate \
  .cache/<issuer>-<prospectus>/proof-pack.json \
  --issuer-file .cache/<issuer>-<prospectus>/issuer.json
```

Hash the exact validated bytes:

```sh
just yieldia hash file \
  .cache/<issuer>-<prospectus>/proof-pack.json
```

Copy the result into `prospectus.md` as `proof_pack_hash`. Any later proof-pack edit requires recomputing this hash.

### 6. Validate the complete local pair

```sh
just yieldia prospectus validate \
  .cache/<issuer>-<prospectus>/prospectus.md \
  --proof-pack-file .cache/<issuer>-<prospectus>/proof-pack.json
```

The command must report the expected `prospectus_id_hash`, `terms_hash`, and `proof_pack_hash`, plus the final exact-byte `document_hash`.

### 7. Publish the exact bytes

Copy the validated pair into this repository, commit both files together, and push them before contacting Solana:

```sh
mkdir -p /absolute/path/to/devnet-data/<issuer>/<prospectus>
cp \
  .cache/<issuer>-<prospectus>/prospectus.md \
  .cache/<issuer>-<prospectus>/proof-pack.json \
  /absolute/path/to/devnet-data/<issuer>/<prospectus>/

git -C /absolute/path/to/devnet-data add \
  <issuer>/<prospectus>/prospectus.md \
  <issuer>/<prospectus>/proof-pack.json
git -C /absolute/path/to/devnet-data commit -m "Add <display-name> prospectus"
git -C /absolute/path/to/devnet-data push
```

### 8. Simulate registration

```sh
just yieldia prospectus register \
  https://raw.githubusercontent.com/yieldia-labs/devnet-data/main/<issuer>/<prospectus>/prospectus.md \
  --rpc-url https://api.devnet.solana.com \
  --signer <authority-address>
```

Without `--submit` the command downloads and validates the published pair, derives and checks the Prospectus PDA, and simulates the unsigned transaction without reading a keypair, signing, or submitting anything. Check the cluster genesis hash, author, Issuer, Prospectus PDA, treasury, mints, hashes, fee, and compute units.

`--signer` has exactly one correct value here: the `author_pubkey` the proof pack names. The command compares them and refuses a disagreement with `provenance.author_mismatch`, which is the same check the submission runs — so this step predicts the next one instead of passing for a signer that would then be refused.

### 9. Register the prospectus

```sh
just yieldia prospectus register \
  https://raw.githubusercontent.com/yieldia-labs/devnet-data/main/<issuer>/<prospectus>/prospectus.md \
  --rpc-url https://api.devnet.solana.com \
  --keypair /absolute/path/to/yieldia-keys/devnet/issuers/<issuer>-authority.json \
  --submit
```

The issuer authority keypair must match `author_pubkey`; it signs the transaction and pays the fee and account rent. Verify the confirmed Prospectus PDA, signature, and slot. No separate registration file is required: the PDA is deterministic and already stored in the proof pack. If confirmation is unavailable after submission, inspect the reported signature and PDA before retrying.

After registration, keep both published files byte-stable. The onchain Prospectus stores their exact hashes, and changing either raw GitHub resource would make the published bytes disagree with the registered account.

Never commit keypairs, seed phrases, private keys, or `.env` files to this repository.
